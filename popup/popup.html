About & Privacy

Field Inspector reads only the HTML of the page you're currently viewing, entirely inside your browser. By default it never modifies form data — clicking a field only opens a read-only info panel, because the click is stopped before it reaches the page.

If you turn off Intercept clicks above (click-through mode), your clicks reach the page normally and can change form data exactly as they would without the extension. The info panel still opens alongside.

Values belonging to password, hidden-token and other secret-named fields are redacted — they never appear in the panel, in Copy All, or in JSON output unless you explicitly turn on Show sensitive values above.

Odoo Developer Mode is the one exception to "nothing ever leaves your browser": when it's on and a clicked field is recognized as an Odoo field, the field's model + technical name (never its value) are sent to the same Odoo server you're already logged into, to fetch that field's real definition. In the same mode the extension reads one fixed, hard-coded setting from that server (web.base.build.description, at most once per tab) to learn your Odoo version, which it uses to build a deep link in the URL style your version supports. Inspecting an Odoo button (in click-through mode, or by picking it in the Field Finder) sends just that button's model + method/action name to the same server, to look its own declaration up — never the button's label, the record it targets, or any record data. Normal clicks on buttons are never intercepted. In the same mode the extension also reads view metadata for that model — which view XML ID you're looking at, what it inherits from, and what attributes a field or button declared there — and never downloads a view's source XML. Turn it off above to disable all of this — everything else keeps working.

Your theme, accent color, density and debug switch are your own preferences: they are stored locally, never transmitted, and contain no page data. Everything you can set in this popup is also available in full on the extension's Settings page — open it with the All settings button below Enable Inspector, or from the extensions menu. It opens in its own tab with a live preview of the actual panel, and it only reads and writes these same local settings: it has no access to any page you are viewing. If a page URL carries ?debug=1 or ?debug=0, that is read only inside that page's own tab, is never stored, and cannot turn the inspector on by itself. The accent color is also used for the outlines the extension draws around inspected fields; those are removed again when you turn the inspector off.

Permissions used:

  • activeTab / scripting — inject the inspector only into the tab you explicitly enable it on.
  • storage — remember your preferences (this popup's settings, the Settings page, and the list of remembered sites) locally in your browser.
  • optional host access — only if you turn on Auto-enable on this site, Chrome asks you to allow access to that one origin. It is used for nothing except re-injecting the inspector when you load a page there. The list of remembered sites is shown in this popup and on the Settings page.

With Auto-enable on this site off, the extension requests no host access at all and never runs in the background on sites you haven't activated it on. Turning auto-enable off here also gives the access back to Chrome immediately.
